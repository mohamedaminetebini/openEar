# Manufacturer protocol research

This research includes historical browser feasibility findings. Openear now ships only as a Tauri desktop app; no browser transport or manufacturer command adapter is installed.

Reviewed upstream documentation and source on 2026-10-10. These are integration candidates, not Openear compatibility claims. No manufacturer commands below are registered or sent by the application. Service access, firmware behavior, acknowledgement semantics, and physical safety need validation before an adapter ships.

## Identifiers and captured command evidence

For Bose, upstream [`connection.rs`](https://github.com/NerdySouth/bozo/blob/main/crates/bozod/src/ble/connection.rs) selects writable/notification characteristics `D417C028-9818-4354-99D1-2AC09D074591` and `C65B8F2F-AEE2-4C89-B758-BC4892D6F2D8`. It uses framed writes without response and notification reassembly. These are characteristic identifiers, not a verified browser service permission list.

Upstream [`battery.rs`](https://github.com/NerdySouth/bozo/blob/main/crates/bozo-proto/src/protocol/battery.rs) tests a battery request serialized as `02 02 01 00`. Its parser fixture includes `85, 01, 2C, 00`, interpreted as 85%, 300 remaining minutes, and component zero. This is evidence from upstream tests, not a packet validated against a device here. A browser adapter needs the complete framing and response-matching protocol, not just these bytes.

Sennheiser's [`ble.rs`](https://github.com/gjabell/momentumctl/blob/main/src/ble.rs) registers RFCOMM profile UUID `a2129ff3-081b-4c45-8afe-469d9c4842ec`. That UUID is not a BLE GATT service to request from the browser. No Sennheiser packets are implemented here.

For Soundcore and Sony, transport restrictions already block reuse of the reviewed implementations in a browser-only adapter. Their model-specific payloads and firmware differences need a separate native integration review. JBL's reviewed speaker commands are outside this headphone MVP's scope.

## Next safe integration

Verify the standard battery adapter on a real BLE headphone first. For a manufacturer candidate, investigate Bose's BLE service and characteristic permissions on the exact tested model, record redacted responses, and confirm acknowledgement/state readback before exposing writable controls. Do not request guessed services or send isolated fixture bytes.

Upstream branches can change. Before implementing, pin an exact reviewed commit and license, add response fixtures and protocol timeout tests, and document the physical firmware/browser matrix. Native-only implementations belong behind the future authorized bridge described in [native-bridge.md](native-bridge.md).
